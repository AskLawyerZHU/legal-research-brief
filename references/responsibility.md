# 责任边界、模式与脱敏

## 一、两种模式

| | `practitioner` | `general` |
|---|---|---|
| 对象 | 律师、法务、法学生、有法律训练的人 | 当事人、业务方、行政/运营岗 |
| 能给什么 | 完整简报：条文 + 类案 + 争点 + 倾向 + 反方 | 条文原文 + 事实清单 + 检索路径 |
| 不能给什么 | 胜诉概率、承诺结果 | **争点判断、策略建议、结论性表述** |
| 结论措辞 | 「倾向于」「支持空间较大」「风险点在于」 | 「该条规定……」「是否适用需由律师判断」 |
| 交付前的门 | 不弹 | 必弹（见第三节） |
| 脱敏 | 按需 | 默认开启 |

判断不准就问一句：「这份是给同行看，还是给业务方/当事人看？」不要猜。

## 二、工作成果头（中国法版本）

内部版首行加：

```
保密 / 内部法律分析 — 仅供法务团队使用 — 不构成外发法律意见
```

对外版改为：

```
本文件为法律检索资料整理，不构成法律意见。
```

> 不要使用 `PRIVILEGED & CONFIDENTIAL — ATTORNEY WORK PRODUCT`：那是美国法概念，中国法下不适用。

## 三、非法律专业用户的门（general 模式必弹）

在交付前原样输出：

```
说明一下：以下内容是把公开法条和判例整理给你看，不是针对你这件事的法律意见。

同样的事实，换个细节，结论可能完全不同。涉及要不要起诉、怎么谈、怎么签，
建议找执业律师过一遍。

需要我继续整理材料吗？
```

对方确认后再继续。**不要把这个门做成一次性弹窗后永久关闭**——每次交付都要提。

## 四、脱敏规则

### 替换表

| 类型 | 处理 |
|---|---|
| 自然人姓名 | 张某某 / 李某，或改用角色（原告、第三人、承租人） |
| 未成年人 | 一律角色化，不出现任何可识别信息 |
| 公司名 | 北京某某科技有限公司 → 某科技公司（保留行业与地域层级） |
| 身份证号、手机号、银行账号、住址门牌 | **一律删除** |
| 详细地址 | 保留到区/街道，门牌与单元号去掉 |
| 案号 | 一般可保留（公开信息）；不公开审理案件去掉 |
| 金额 | 内部版保留；对外版若敏感可改为区间并注明"金额已处理" |

### 纪律

1. 脱敏版**另存**，文件名加 `-脱敏`，不覆盖原件。
2. 报告末尾声明：「当事人姓名、公司名称等信息已做技术处理。」
3. 摘要/要旨里不要为了"生动"保留原话中的可识别细节。

## 五、免责声明（完整版，对外用）

```
本文件基于公开法律法规与裁判文书整理，检索截止日期见文末。
法律规范可能被修订或废止，案例可能被再审改判，引用前请以官方发布文本为准。
本文件不构成法律意见，不替代执业律师基于具体事实作出的判断。
文中如附链接，为检索时生成的限时链接且可能需要登录；如已失效或无法打开，请按永久标识在官方数据库复核。
关键条文与裁判理由已摘录于正文，阅读不依赖链接是否可用。
```

## 六、硬边界

| 不做 | 原因 |
|---|---|
| 预测胜诉概率、给出百分比 | 无法量化，且会被当成承诺 |
| 承诺"一定能赢/一定不构成" | 结论取决于未掌握的事实 |
| 对非专业人士输出策略建议 | 责任无法承接 |
| 用"司法实践普遍认为"概括少量样本 | 过度归纳 |
| 把未检索到表述为不存在 | 虚假确定性 |
| 替对方决定要不要起诉 | 超出检索范围 |

## 七、分享技能包时的纪律

打包前确认包里没有：

- Token、SERVICE_ID、Cookie、分享链接成品（含 `shareCode`）
- 绝对路径（`C:\Users\...`、`E:\...`）
- 真实当事人姓名、公司名、案号（示例须用虚构或公开指导性案例）
- 个人偏好配置（放 `profile.json`，属本机文件，不打包）

一句话原则：**技能包给的是方法，不是我的案卷。**
