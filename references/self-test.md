# 自检清单

首次安装、换环境、或怀疑跑不通时，逐条做一遍。**不要跳过第 3 条**，它决定这个技能是否可信。

## 一、环境（5 分钟）

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 连接器是否真的连通 | 调一次 `search_articles(keyword="民法典", top_k=1)`，**返回条目**才算通过；只看配置显示"已连接"不算 |
| 2 | 类案库是否可用 | `search_cases(cause_of_action=["合同纠纷"], top_k=1)` 有返回 |
| 3 | 权威案例库是否可用 | `search_authoritative_cases(top_k=1)` 有返回 |
| 4 | 回链实际能力 | 对任一案例调 `get_case_detail`，读 `share_access`。**本机实测为 `login_required`＋`share_expires_at: null`，属正常**——通过标准是「如实记录实际值」，不是「必须免登录」。读到 `login_free` 时须同时记下到期日 |
| 5 | 工具名是否对得上 | 五个动作全部能调通，无"工具不存在"错误 |

五项全过 → 能力卡写「全功能」；1–4 有缺 → 按 `adapters/no-db.md` 降级；5 不过 → 回到 `adapters/yuandian.md` 第二节核对现用名。

## 二、输出结构（跑一个虚构问题）

用不含真实当事人的假设问题（如"假设合同约定成年后给付教育金，一方拒付"），检查：

- [ ] 结论在一页内说完，不超过 5 行
- [ ] 每条法条有：条款号、时效、来源库、检索日期
- [ ] 每条案例有：案号、法院、审级、裁判日期、效力类型
- [ ] 每个争点都有"反方"段落
- [ ] 末尾有检索范围声明（含未覆盖项）
- [ ] 没有"司法实践普遍认为"这类无源表述

## 三、无库降级（最关键）

**临时断开数据库**（或直接问"如果没有数据库你会怎么做"），检查：

- [ ] 输出的是检索式清单 + `[待检索]` + 接入指引
- [ ] **没有**出现任何具体条文原文
- [ ] **没有**出现任何案号
- [ ] 明确说了"未检索到"，而不是"不存在"

任何一条不过 → 说明兜底逻辑漏了，回到 `SKILL.md`「三条不可协商的规则」第 2 条修。

## 四、引用可复核

随机抽 3 条引用，只用永久标识（不点链接）去官方网站检索：

- [ ] 3 条都能找到对应条文/文书
- [ ] 时效状态与报告一致
- [ ] 条款号没有错位（最常见的错）

有任何一条找不到 → 该条必须降级为 `[待检索]` 或删除。

## 五、分享包（发出前）

在技能目录里全文搜索，命中任何一项就不能发：

| 搜什么 | 期望 |
|---|---|
| 真实凭证值（`sk-` 开头的串、长 base64、实际 SERVICE_ID） | 0 处 |
| 绝对路径（`C:\Users\…`、`E:\…`） | 0 处 |
| 真实当事人姓名 | 0 处（示例须虚构） |
| 真实案号 | 0 处（除非是公开指导性案例） |
| `.workbuddy/mcp.json` 的实际内容 | 不出现 |

> 配置示例里的 `{TOKEN}`、`{SERVICE_ID}`、`Bearer` 属于占位写法，允许保留——它们不含真实值。检查的是**值**，不是关键词。

再确认：

- [ ] `SKILL.md` frontmatter 有 `agent_created: true`
- [ ] `description` 是第三人称，且写清了触发场景
- [ ] `profile.json` 不在包内（只保留 `profile.example.json`）
- [ ] `README.md` 写清了适配环境与配库步骤
- [ ] `CHANGELOG.md` 注明了法律数据截止日

## 六、留痕

自检结果写一行记在 `CHANGELOG.md` 的对应版本下，例如：

```
v1.0.0 自检 2026-11-14：环境 5/5 通过；无库降级通过；抽样复核 3/3；包内敏感项 0
```
