# 简报与报告结构

## 一、简报（默认交付物）

六节，顺序不能调——先给结论，再给证据，最后给边界。

### 1. 一页结论（≤5 行）

- 一句话回答最初的问题
- 支撑它的 1–2 条核心依据（带条号/案号）
- 明确的不确定项（有几条未复核、哪块缺类案）

不要在这一节写"综上所述"式空话。

### 2. 法条索引（表）

| 规范 | 条款 | 要旨（一句） | 时效 | 来源 |
|---|---|---|---|---|
| 《民法典》 | 第 509 条 | 按约全面履行 | 现行有效 | 元典 2026-11-14 |

按 **效力级别降序**（法律 > 司法解释 > 行政法规 > 地方文件），同级按相关性。

### 3. 类案要旨（表）

| 案号 | 法院／审级 | 裁判日期 | 争议焦点 | 裁判要旨（自述） | 相关性 | 效力 |
|---|---|---|---|---|---|---|

- 相关性只填 高／中／低（低相关只进附录）
- 效力填：指导性案例／公报案例／典型案例／普通案例
- 二审改判的，要旨里写明改判理由

### 4. 争点分析（按要件逐条）

每个争点一个小区块：

```
争点：原告主体是否适格
法条：《民法典》第 X 条 + 婚家编解释（一）第 X 条
类案：（2025）…号（高相关）、（2024）…号（中相关，相反结论）
判断：倾向于……，理由三点
反方：对方可能主张……，可用……回应
未决：地方口径未检索到，建议补检辽宁地区
```

**"判断"必须给理由，"反方"必须写**——没有反方段落的争点分析，是半成品。

> 这套五项格式**只用于简报**。报告网页里把同样的内容织进叙述或表格，不要照搬填空——读者要的是论证过程，不是结构清单。

### 5. 反方观点与风险

- 对立案例清单（哪怕只有一件，也要列）
- 己方论证最脆弱的环节
- 如果关键依据被推翻，结论会怎么变

### 6. 检索范围与说明

用 `source-tagging.md` 第六节的模板，逐项填。**这一节不能省**，它是这份简报可被信任的前提。

## 二、报告网页

用 `assets/report-template.html` 起步。**它是骨架与必备元素清单，不是美术标准**——配色、字体、表格样式、留白节奏、信息层级、要不要分栏，全部按内容自行设计。目标读者拿到的应像一份卷宗／底稿，而不是一张后台管理系统截图。

**动手前先定三件事，每次都定，不许沿用上一份：**

1. **读者是谁**——自己办案带着走／给当事人或合伙人看／对外发布。三种版式不同：第一种要索引，第二种要结论和赢面，第三种要故事线。
2. **第一屏回答什么**——报告最上面那一屏必须能直接回答本篇的核心问题。答不出来，是结论没提炼出来，不是版式问题，回去改结论。
3. **有没有比表格更好的表达**——门槛递进、攻防对照、后果分岔这类结构，画成图比排成表清楚。表格只用于「多条同类条目并列」。

**以下五条是硬约束（其余样式都可以改）：**

1. 顶部：标题 + 案由/问题 + 检索日期 + 来源库
2. 结论块：与简报第 1 节一致，视觉上最突出
3. 法条块：条文原文字号不小于正文（底色不限）
4. 类案块：表格，案号可点（若为 login_free 链接）
5. 底部：免责声明 + 链接有效期提示 + 脱敏声明（若已脱敏）

**报告网页不是简报的排版版。** 简报六节是检索底稿的结构，给同行复核用；报告网页的读者是办案的人，他按「办案的问题顺序」读，不按检索流程读。**动手前先把读者要问的问题按顺序列出来，章节就按这个序列编排**，不能照搬简报六节。执业者模式的典型序列：

> 能不能赔 → 凭什么（法条）→ 卡在哪（关键要件）→ 别人怎么判（类案）→ 对方会拿什么挡（免责与抗辩）→ 打不赢怎么办（退路）→ 还剩几天（期限）→ 还缺什么（待核验）→ **现在做什么（下一步动作）**

**七条结构规则：**

1. **章节标题写结论，不写名词。**「最要命的那个要件：欺诈故意」能当目录读；「争点分析」「口径分歧」是档案柜标签。检验方法：只看目录，能不能复述出本案的攻防。
2. **结论区给「情形 → 结果」映射**，不给叙述。什么情形能拿到、什么情形基本拿不到，各 3–4 条，让读者对号入座；比要件论述更可用。
3. **类案按效力层级分层**（权威／高院 → 普通裁判），攻守作为每行的属性，不作为分组维度——「高院怎么判」和「本地中院怎么判」是两个层级的依据，混排会丢掉效力信息。
4. **多条同类条目用表格，不用卡片。** 卡片只给「每张内容都不一样」的结构（如要件门槛）；十几个案子排成卡片，会滚动到失去耐心。
5. **执业者模式必须有「下一步动作」**：编号清单，每条一个动作＋一句依据（案号或条文）。这是全篇对办案人最有用的一节，不是可选项。
6. **元任务不占章节**：口径分歧并入相关要件章节讨论；关系图判断一句话带过或放附录。技能要求的自检不能变成读者看到的交付清单。
7. **待核验独立成节**，用表格：条目｜缺什么｜影响｜怎么补。不要散在图注或检索说明里。

生成后逐项自检：

- [ ] 每条引用都有永久标识（不只有链接）
- [ ] 每张进正文的类案都能定位：有案号，或法院＋审级＋裁判日期三项齐全。三者都没有的（如只写「某某法院某案」的典型案例），只能进附录，不进正文
- [ ] 失效/未复核的条目已标注
- [ ] 没有 Token、内网地址、绝对路径
- [ ] 若对外，姓名/公司/地址已替换
- [ ] 单文件可离线打开（内联样式，无外部依赖）

## 三、对外版的改动（给客户/合伙人）

在同一份底稿上改，不要另起一份：

| 项 | 内部版 | 对外版 |
|---|---|---|
| 策略倾向（"胜诉空间较大"） | 保留 | **删除**，只留规范与类案 |
| 反方风险 | 完整 | 可概括，不得删净 |
| 当事人信息 | 真实 | 脱敏 |
| 工作成果头 | 保留 | 改为对外声明 |
| 免责 | 简版 | 完整版（见 responsibility.md） |

改完另存，文件名加 `-外发`，**不覆盖内部版**。
