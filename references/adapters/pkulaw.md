# 适配器 · 北大法宝

数据范围：法律法规库 + 司法案例库（需订阅并配置 Token）。

> ⚠️ **本机当前未启用**（connector 状态为 disabled）。以下为接入方式与能力对应；**具体工具名以启用后实际暴露的为准**，不要凭本文件猜测调用。

## 一、配置位置（WorkBuddy，不是 Claude）

旧文档里的 `mcpServers` JSON 是 Claude Code / Desktop 的写法，WorkBuddy 要写到：

```
~/.workbuddy/mcp.json
```

并合并进已有的 `mcpServers` 节点，不要覆盖其他 server：

```json
{
  "mcpServers": {
    "pkulaw-law": {
      "url": "https://apim-gw.pkulaw.com/{SERVICE_ID}/mcp",
      "headers": { "Authorization": "Bearer {TOKEN}" }
    }
  }
}
```

- `SERVICE_ID` 与 `TOKEN` 在法宝 MCP 控制台获取，**只写在本机配置文件，绝不进技能包**。
- 法条检索、案例检索是两个不同 `SERVICE_ID`，通常配成两个 server（如 `pkulaw-law` / `pkulaw-case`）。
- 配好后需在连接器管理页对新 server 点「信任」才会生效。

|---|---|---|

**不要照抄元典的工具名。** 两套接口字段不同，硬套会返回空或报错。

## 三、返回字段的核对点

拿到结果后逐条确认三件事，缺一就降级为 `[待核验]`：

1. **时效状态**：是否现行有效、有无修订版本
2. **效力级别**：法律／行政法规／司法解释／地方性法规……
3. **裁判要素**（案例）：案号、审理法院、裁判日期、审级

法宝不同服务返回的字段命名不统一，以实际返回为准，不要用元典的字段名硬取。

## 四、与元典并存时

两个都可用时：

- **不必双库全跑**，按 `references/profile.json` 的 `primary_source` 定主库，另一库只用于第四步交叉复核。
- 复核时若两库结论不同，按「口径分歧」处理，并列呈现，不要择一。
- 报告里必须写明数据来源库名称与检索日期——同一份报告混用两个库时，逐条标注。

## 五、失败处理

- 鉴权失败 → 停，提示检查 Token 与控制台订阅，不重试三次以上。
- 返回为空但库应覆盖 → 换关键词或语义检索重试一次；仍为空则写 `[待检索]`，并注明「该库未返回，可能未收录」。
- 工具名对不上 → 回到第二节重列工具，不要猜。
